## WebHTV serverless/ 目录梳理（只读探索，未改代码）

- `serverless/` 是 WebHTV 的**自建服务端**目录，5 个同协议实现：
  - `webhtv-remote-cloudflare` — CF Worker + Durable Object（`WebHTVRemoteRelayDO` + `WebHTVPlaybackSyncDO`），唯一把 relay 状态也持久化的版本
  - `webhtv-remote-deno` — Deno Deploy，playback 用 Deno KV（manifest + 48KiB 分块）
  - `webhtv-remote-vercel` — Vercel Edge，playback 需 Vercel KV / Upstash Redis REST，未配置直接 503 不降级
  - `webhtv-remote-go` / `webhtv-remote-rust` — 单二进制，额外提供 WebSocket `/api/device/ws`（App 优先 WS，失败回退轮询），playback 落本地 JSON（临时文件 + fsync + 原子 rename，0600），`dist/` 内含预编译 linux-amd64/arm64
- 两套能力（共用域名、状态隔离）：
  1. **远程托管 relay**：`/api/device/register`、`/api/device/bind-code`、`/api/groups/claim`、`/api/devices`、`/api/commands`、`/api/sync/create` 等；流程 = 注册设备 → 6 位绑定码 → 主控端 claim → 下发 export/restore 命令 + 一次性分片中转
  2. **观影记录同步**：`/api/playback/sync`（POST 进度/完播/删除，GET 按 `X-WebHTV-Since` 拉增量），头 `X-WebHTV-Token` + `X-WebHTV-Config-Key`，只存 SHA-256 分区键；限 128KiB / 单批 100 / 单次拉 1000；墓碑保留 90 天
- 关键约定：请求头 `X-WebHTV-Origin` 优先作为 `serverOrigin`（避免 workers.dev 与自定义域名导致绑定码校验失败）；`/api/server/capabilities` 上报 serverMode / relayMode / playbackSync
- App 侧对接：`app/src/main/java/com/fongmi/android/tv/remote/RemoteClient.java`（HTTP + WS 地址拼接）、`RemoteSyncTransfer.java`
- 注意：`webhome-devkit/` 目录在本工作区不存在（README 提到放在该目录 + 独立 CNB 仓库），相关文档未克隆到这里
